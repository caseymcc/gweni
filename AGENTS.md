# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

gweni ("GUI Without Extravagant Nonsense") is a C++17 retained-mode GUI library, forked from Garry Newman's **GWEN** (MIT) and reworked to be OpenGL-aware. The core idea separating it from GWEN: instead of redrawing every widget each frame in immediate mode, controls allocate persistent renderer **primitives** and only regenerate/update them when their state actually changes. The long-term goal is good performance on modern OpenGL (3.0+ core profile) and eventually Vulkan.

The library builds as a static/object library plus example executables. Tests are run with CTest (see "Tests" under "Building"; a short version for humans is in [`docs/building.md`](docs/building.md)).

## Building

**All builds and dependency operations run inside the build container — never directly on a developer's host.** The toolchain, vcpkg, and all build tooling live in the container.

### Which situation are you in? Test `VCPKG_ROOT`

Everything below depends on whether you are *outside* the container (a developer on their own machine) or *already inside* it. Check before you run anything:

```bash
[ -n "$VCPKG_ROOT" ] && echo "inside the container" || echo "on a host — go through run_docker.sh"
```

`VCPKG_ROOT=/opt/vcpkg` is baked into the image (`Dockerfile`), so if it is set you are inside the build container and already have cmake, the compilers and vcpkg. If it is unset you are on a host; `generate.sh` detects this itself and refuses to run, pointing you at `run_docker.sh`.

### Inside the container (`VCPKG_ROOT` is set)

Run the same two steps directly — there is no docker inside the container, so `run_docker.sh` cannot work here:

```bash
./generate.sh linux                   # configure build_linux_x64_debug/
cmake --build build_linux_x64_debug -j # build
```

This is the case for an automated agent run: the agent image is built FROM this repo's own `Dockerfile`, so the container is already the environment described here. The repo is at the working directory, not at `run_docker.sh`'s `/home/developer/gweni`. Whether the vcpkg cache is available depends on how the container was started: check `VCPKG_DEFAULT_BINARY_CACHE`/`VCPKG_DOWNLOADS` — if they are unset, nothing mounted `/vcpkg-cache` and the dependency build starts cold (slow, and not reused by the next run).

### On a host machine (`VCPKG_ROOT` is unset)

`run_docker.sh` builds an Ubuntu 22.04 image (`Dockerfile`), creates a container that mounts the repo at `/home/developer/gweni`, and either attaches a shell or runs a command you pass it:

```bash
./run_docker.sh                       # interactive shell in the container
./run_docker.sh ./generate.sh linux   # run a single command in the container
./run_docker.sh cmake --build build_linux_x64_debug -j
```

Flags (before the command): `-r` rebuild the image, `-s` force-restart the container.

This path always gets a persistent vcpkg cache: `run_docker.sh` creates `.vcpkg-cache/` in the repo and mounts it at `/vcpkg-cache`, setting `VCPKG_DEFAULT_BINARY_CACHE` and `VCPKG_DOWNLOADS` into it, so the slow first dependency build is reused across container runs. `.vcpkg-cache/` and `vcpkg_installed/` are git-ignored.

### `generate.sh` is how this project is configured

**The build always goes through `generate.sh`.** It only runs `cmake` **configuration** (it does not build), and it is what points CMake at the vcpkg toolchain (`$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake`), chainloads `cmake/linux_toolchain.cmake`, pins the `x64-linux` triplet and selects the renderer options. A hand-written `cmake -B ...` configure line skips all of that and produces a differently-configured tree — it is not a valid way to build this project, even inside the container.

The commands in this section are the in-container form; from a host, prefix each with `./run_docker.sh`.

```bash
./generate.sh linux                  # configures build_linux_x64_debug/ (OpenGL core renderer)
./generate.sh linux release          # release build dir
./generate.sh linux -DSOME_OPT=ON    # any -D... arg is passed through to cmake
./generate.sh linux asan             # AddressSanitizer tree, build_linux_x64_debug_asan/ (see "ASAN tree")
./generate.sh linux profile          # profiling tree, build_linux_x64_profile/ (see "Profile tree")
```

Dependencies are managed by **vcpkg** (manifest `vcpkg.json` at the repo root), bootstrapped into the image at `/opt/vcpkg`; `generate.sh` triggers the manifest install at configure time.

Then build into the generated directory (named `build_<platform>_<arch>_<buildtype>`, `<buildtype>` being `debug`, `release` or `profile`, with `_asan` appended for an ASAN tree):

```bash
cmake --build build_linux_x64_debug -j
```

The Linux example binaries land in `build_linux_x64_debug/examples/openglcore/` (`OpenGLCore`, `ControlTest`). The build copies `resources/` next to them and they load it through `RelativeToExecutablePaths("resources")`, so they run from any cwd. ControlTest's `--scale <s>` (or `GWENI_SCALE`; the flag wins) renders at s device px per logical unit: the canvas is `--size` logical, the framebuffer and PNGs `round(size*s)`, and scripted coordinates, the scenarios' sizes and `--dump-bounds` stay logical. `OpenGLCore --scale <s>` (or `GWENI_SCALE`) keeps its 1024x768 framebuffer and makes the canvas `round(1024x768/s)` logical, so the UI is drawn s times as large. In a window both multiply the OS content scale (`glfwGetWindowContentScale`, followed by its callback; an offscreen capture and EGL count as 1), through `capture::fitCanvasToWindow`, which also keeps `input::GLFW3`'s cursor mapping (`windowToLogical`) current (`docs/architecture.md` → "Where the scale comes from"). `--resources <dir>` (relative to the cwd, or absolute) loads the skin, fonts and textures from `<dir>` instead, e.g. `--resources resources` from the repo root to pick up live `DefaultSkin.json` edits without a rebuild. A missing resource dir, skin config or default font prints one line naming the path tried and exits non-zero. A capture runs on a stepped clock (1/60 s per frame); `--stats` freezes it, so an idle frame is genuinely idle, and `--stats-clock step` keeps it stepping, for the counters of something that waits on time (a tooltip's delay, an animation). Both exes take `--headless` with a capture (`OpenGLCore --screenshot`/`--frames`, ControlTest's `--shot`, `--shot-all`, ...): it goes straight to the surfaceless-EGL context instead of trying a GLFW window first, so a capture renders the same whether or not a display exists. Without a capture it is an error, and so it is in a build without the EGL path (`GWENI_EXAMPLE_EGL` off).

### Running the examples

`./run.sh [-b] [debug|release] [asan] [opengl|controltest] [args...]` runs one of them from any cwd (defaults `debug`, `opengl`; `asan` is `build_linux_x64_debug_asan/`). The first argument that is none of its words, and everything after it, goes to the exe unchanged, and the exe runs in the caller's cwd, so relative `--shot`/`--screenshot`/`--resources` paths mean what was typed. It never injects `--resources`. `-b` builds first (`cmake --build`, through `./run_docker.sh` when `VCPKG_ROOT` is unset) and stops with the build's exit status if it fails; without `-b` it never builds. A missing build tree or exe prints the path and the `generate.sh`/`cmake --build` commands, and exits 1. `./run.sh -h` is its usage; `./run.sh controltest --help` is ControlTest's. Nothing may depend on `run.sh`: scripts and tests call the exes directly.

- On a host: `./run.sh`, `./run.sh -b`, `./run.sh controltest --control ButtonDemo`. The container-built exes need the host's glibc ≥ 2.34, GCC 11+ libstdc++ (`GLIBCXX_3.4.29`) and a glvnd GL driver (`libGLX.so.0`, `libOpenGL.so.0`, `libEGL.so.1`), e.g. Ubuntu 22.04+, Debian 12+, Fedora 35+; the vcpkg deps are static. The image is built with the host UID/GID, so the build output is owned by the developer.
- In the container (an agent run) there is no display, so only the headless modes work: `./run.sh controltest --headless --shot /tmp/x.png` or `./run.sh --headless --screenshot /tmp/x.png`, under the GPU lock. Plain `./run.sh` execs `OpenGLCore`, which fails to open a window; that is expected.

### Regenerating the UI samples

The sample PNGs under `docs/images/` (embedded by `README.md`) are checked in and regenerated by one script, run inside the container after a normal build (from any cwd):

```bash
./tools/capture_samples.sh                 # rewrite docs/images/
./tools/capture_samples.sh --check         # compare with docs/images/, write nothing there
./tools/capture_samples.sh --bin-dir DIR   # take OpenGLCore/ControlTest from DIR
```

It captures the hero demo (`OpenGLCore --headless --demo`) and the gallery controls (`ControlTest --headless --control`) with `--headless`, always through the surfaceless-EGL path, so no display is needed and having one changes nothing. It loads the repo's `resources/` (`--resources`), not the copy next to the exes. `--bin-dir` defaults to `build_linux_x64_debug/examples/openglcore`. `--check` captures the same set through the same `capture()` into a `mktemp -d` dir and compares each PNG byte for byte with `docs/images/`, printing `differs: X.png`, `missing from docs/images: X.png` or `not in the sample set: X.png` (any other PNG there). It exits 1 on any of them and keeps the scratch dir, printing its path so the new captures can be looked at. If everything matches it exits 0 and removes the dir. The `SAMPLES` list at the top of the script is the interface: edit it to change the set, and update the gallery table in `README.md` to match, since it embeds each PNG by path in that order. Re-running on an unchanged tree produces byte-identical PNGs.

CTest runs `--check` as `docs_samples`, in the `gpu` set (see "Tests"). So **a commit that changes how a sample looks must regenerate the samples in that same commit**: run the script, look at every PNG that changed, and commit them with the change. The bytes match only inside the pinned build container (its Mesa llvmpipe and compiler), so a `docs_samples` or `--check` failure on a host means nothing. The debug, ASAN and release trees render the same bytes, so `docs_samples` is registered in every tree. A difference between them is a bug, not -O2 pixel noise: the release-only 20 px wider PropertyTree of issue #248 was undefined behaviour (the CheckBox and ComboBox renderers `static_cast`ing the `property::` controls that share their names).

```bash

ctest --test-dir build_linux_x64_debug -L gpu     # only the tests that need a GL context
ctest --test-dir build_linux_x64_debug -LE gpu    # only the ones that don't (the headless unit tests), no GPU lock
```

### ASAN tree

`./generate.sh linux asan` configures a second tree, `build_linux_x64_debug_asan/` (`asan` combines with `release` too: `build_linux_x64_release_asan/`), with `-DGWENI_SANITIZE=address`. It builds and tests like the plain one:

```bash
./generate.sh linux asan
cmake --build build_linux_x64_debug_asan -j
mm run --lock gpu -- ctest --test-dir build_linux_x64_debug_asan --output-on-failure
```

The sanitizer flags are set before `deps/` is added, so gweni, the examples, the tests and the vendored freetype-gl and imglib are instrumented. The vcpkg-installed dependencies are not. In that tree every test runs with `ASAN_OPTIONS=detect_leaks=0:abort_on_error=1` (`tests/CMakeLists.txt`): Mesa/EGL leak at exit and that is not ours, so leak checking is off and only memory errors fail a test. An ASAN report aborts the process, and that fails the test, including a ControlTest child of `determinism.cmake`. Run one binary by hand with the same `ASAN_OPTIONS`.

The heap-string case in `tests/textLength.cpp` is a real check only in this tree. If `OpenGLCore` passes freetype-gl a byte count again (the `cca344a` bug), ASAN reports `heap-buffer-overflow` in `deps/freetype-gl/text-buffer.c`. ControlTest's UnicodeTextDemo also triggers that report.

**ASAN does not catch an over-read that stays inside one object.** ListBoxDemo's original instance of this bug read past a short string held in SSO storage inside `controls::Text`, into the neighbouring `m_font` field. That memory is addressable, so ASAN and valgrind both stay silent. The deterministic trailing-bytes test in `textLength.cpp` exists for that case, and so does the two-process determinism test.

### Benchmarks and profiling

`gweni_bench` (`bench/`, built with `GWENI_BUILD_TESTS` and `GWENI_BUILD_EXAMPLES`, into `build_linux_x64_<type>/bench/`, with its own copy of `resources/` next to it) measures what a frame costs on the full path: gweni, the textured skin and `OpenGLCore` on a surfaceless EGL context (always; it never opens a window). It is for weighing a change, not a gate: nothing in CTest fails on its numbers.

```bash
mm run --lock gpu -- build_linux_x64_release/bench/gweni_bench --scene hover-sweep --n 10000
build_linux_x64_debug/bench/gweni_bench --list     # the scenes: name takes_n= default_n= warmup= frames= scaling= description
build_linux_x64_debug/bench/gweni_bench --help     # options and every output key
```

It runs one **scene** (`--scene`), a tree built in code (not a Demo page, so a page can change without moving the numbers) with the input or edits it drives each frame: `build` (an N-item mix of Labels, Buttons, TextBoxes, CheckBoxWithLabels in nested ScrollControls, a ListBox and an expanded TreeControl; its first frame), `idle` (that tree settled, no input), `hover-sweep` (the mouse one row down a ListBox of N rows per frame), `set-text` (`--k` of N Labels, default 10, get a new string of the same length per frame), `type` (a letter typed, every fourth frame a Backspace, in the middle of a focused TextBoxMultiline of N words, a paragraph per 12), `scroll` (the wheel one notch per frame over a fixed-size ScrollControl of N 30-unit Button rows, down to the end and back up; a notch is `30*(1 - viewable/content)` units, about one row at large N), `drag` (a Window of a fixed 40 controls dragged by its title bar over N Labels, pressed in the last warm-up frame and released in the last measured one), `tree-toggle` (a 50-leaf node near the top of an expanded N-node TreeControl collapsed and expanded in turn), `add-remove` (the oldest of N Labels deleted, outright and with `delayedDelete()` in turn, and a new one added, per frame), `bring-to-front` (the next of 8 cascaded Windows holding N Labels between them brought to the front), `resize` (the build tree, the canvas, target and view between 3/4 of `--size` and `--size`), `scale` (the build tree at `Canvas::setScale` 1.5, 2 and 1 in turn, the target resized to match) and `animate` (`--k` indeterminate ProgressBars and a focused TextBox's blinking caret among N idle Labels, no input; the caret is lit for 1.5 s after the focus, so it warms up 90 frames). Each scene is **`scaling=local`** or **`scaling=linear`** (`--list` and the summary line): a local scene (`idle`, `hover-sweep`, `set-text`, `type`, `drag`, `animate`) changes a fixed part of the tree each frame, so its per-frame counters must be the same at any N (a counter that grows is a finding: the scaling check of `tools/bench.sh` reads this); a linear one touches every control by design (`build`; `add-remove` and `bring-to-front`, through the whole-tree z renumber; `resize` and `scale`, a relayout of everything; `scroll`, where every row moves; `tree-toggle`, where every node below the toggled one moves). `draw_calls` and the idle frame's `flush_us` grow with N in every scene: every frame draws every slot, one draw per index chunk of 16383 slots. `--n`, `--k`, `--frames` (measured), `--warmup` (run first, not reported) default per scene; `--size WxH` (default 1280x800, scale 1), `--resources <dir>`, `--json`. A new scene is a `bench::Scene` subclass and one row in `scenes()` (`bench/scenes.cpp`) with its `Scaling`; its `step(ctx, frame)` gets the warm-up frames as `-warmup..-1`, `ctx.frames` is the measured count, and `ctx.setTarget(size, scale)` resizes the canvas, the offscreen target and the renderer's view as a window's callbacks do.

The output, the interface the scripts parse: one line per measured frame, `scene=<name> n=<N> frame=<i>` then `key=value` pairs, and one `summary` line (`--json`: the same as one object, `frames` and `summary`). Per frame, the wall time of each **phase** in microseconds: `input_us` (the scene's step), `update_us` (`updateCanvas()`), `render_us` (`renderCanvas()` without the renderer's `end()`), `flush_us` (`OpenGLCore::end()`, which is `flush()`: the slot diff, the uploads and the draws, split off by `BenchRenderer`, an `OpenGLCore` subclass in the bench, so the renderer is unchanged) and `gpu_us` (a `glFinish()` after the frame; in the container that is Mesa llvmpipe rasterising on the CPU, `gl_renderer=` in the summary says so, and it is not a GPU's cost). Then the **counters**: `ChangeStats` (`visited`, `controls_changed`, `created`, `visibility`, `geometry`, `background`, `text`), `FrameStats` (`prim_slots_written`, `text_slots_written`, `upload_calls`, `upload_bytes`, `mirror_bytes`, `draw_calls`, `text_draws`, `atlas_upload_calls`, `atlas_upload_bytes`), `LayoutStats` (`layout_passes`, `layout_capped`, `render_layout`), `z_visited`, the live `prim_ids`/`text_ids`, and `allocs`/`alloc_bytes` with `allocs_<phase>`: C++ `operator new` calls on the main thread (the bench replaces the global one, `bench/allocCounter.cpp`; C `malloc`, e.g. freetype-gl's, and Mesa's own threads are not counted). The summary has `scaling=` (the scene's, as `--list` gives it), `controls=` (every control in the tree after the last frame), `construct_us`/`construct_allocs` (`Scene::build()`), `<phase>_us_min/_median/_max` and `<counter>_total/_max`.

The same arguments always give the same counters, and only the times vary: the clock is stepped 1/60 s per frame (`platform::setTimeSource`), the input is the scene's own, and before the scene is built a primer canvas (a small `build` tree) draws two frames and is deleted, so llvmpipe has compiled its shader variants before the measured frames (LLVM's allocations while compiling differ from run to run, and Mesa's on-disk shader cache changes them again). The font atlas's first upload therefore happens in the primer too, not in `build`'s frame. Times come from a release tree. Hold the GPU lock around a run, as for any capture. `bench_smoke` (`bench/smoke.cmake`, label `gpu`) runs every scene in `--list` at N=50 for 3 frames and fails, naming the scene, only if one exits non-zero, crashes or prints the wrong lines.

## Architecture

> Full write-up in [`docs/architecture.md`](docs/architecture.md); summary below.

### Core goal: API-agnostic, change-tracked UI
The whole point of gweni is that **UI logic (layout, padding, docking, hover/highlight/focus, hit-testing) is decoupled from the rendering API**. The same control/skin code is meant to drive OpenGL today and Vulkan (or any backend) later, by implementing one abstract interface — `gweni::renderer::Base` (`include/gweni/platforms/baseRender.h`). The core never makes API calls directly; it only calls that interface. `OpenGLCore` is the only shipped backend; `StubRenderer` (`tests/unit/headlessFixture.h`) is a second implementation of `renderer::Base`, compiled in every build with tests on (the default), so the interface stays implementable outside OpenGL.

The frame is two phases (`examples/openglcore/openglcore.cpp`):
1. **`canvas->updateCanvas()`** — logic only: input, animations (`anim::think()`), layout/docking, z-order, and recording *what changed* per control as a state-change bitmask. No draw calls. It enters only what changed too: there is no per-control `think()`, layout stops at controls with nothing to lay out, and the z indices are renumbered (`Base::renumberZRecursive`, the whole tree) only on a frame after the tree order changed, which `Base` reports through `Canvas::invalidateZOrder()` from `addChild`/`addChildOfLayout`/`removeChild`, `bringToFront`/`sendToBack`/`bringNextToControl` and a skin Control assigned or released. So a settled frame enters no control in either phase (`UpdateStats::zVisited`, `z_visited=` in `ControlTest --stats`; `docs/architecture.md` → "updateCanvas()").
2. **`canvas->renderCanvas()`** — render: `renderer->begin()`, walk the tree, and for each control emit **only the draw-state changes needed**, then `renderer->end()`. A control with `StateChange_Nothing` issues no renderer calls. `addStateChange` also sets `m_childStateChanged` on the `m_actualParent` chain, and `doRender` skips a subtree with nothing pending, so a settled frame enters no control at all (`ChangeStats::visited`, `visited=` in `ControlTest --stats`; `docs/architecture.md` → "renderCanvas()").

A backend may be **immediate** (redraw everything each `drawFilledRect`) or **retained** (primitive ids index a persistent GPU buffer); the same UI code drives both. The performance target is that per-frame cost scales with what changed, not UI size.

### Namespaces & layout
- `gweni::controls` — all widgets, rooted at `controls::Base`. Headers in `include/gweni/controls/`, impls in `source/controls/`.
- `gweni::skin` — draws controls; `simple` (vector) and `textured` (atlas-based, the one the examples use) skins under `skins/`.
- `gweni::renderer` — `renderer::Base` abstract API; the one concrete renderer, `OpenGLCore`, is under `source/platforms/renderers/OpenGLCore/`.
- `gweni::platform` — OS abstractions (clipboard, cursor, file dialogs, timing, window creation) in `platforms/`.
- `gweni::event` — signal/slot system in `events.h`.

Public headers live under `include/gweni/...`; the directory tree there mirrors the `source/...` tree. Note the header path `include/gweni/controls/dialogs/` maps to source `source/controls/dialog/` (singular).

### The retained-primitive model (the important part)
This is what makes gweni different from upstream GWEN and is easy to get wrong:

1. Every `controls::Base` tracks a dirty bitmask via `addStateChange(...)` with flags `StateChange_Created / Visibility / Geometry / Background / Text / Caret` (defined in `controls/base.h`; `Caret` alone is a TextBox blink, which only shows or hides the caret slot). `StateChange_Nothing` means nothing to regenerate.
2. Controls own persistent renderer **primitive IDs** (`primitiveIds.h`: `getPrimitiveId`/`getTextId`/`releasePrimitiveId`). The skin's `Control` objects (`skin.h`) declare `requiredPrimitives()` and have `generate()/update()/remove()` keyed off the control's `State` (`Generate`/`Update`/`Remove`).
3. **Scale:** controls lay out in logical units, and `renderer::Base::translate()` snaps each rect's *edges* to device pixels (`Base::snap(v)=floor(v*scale+0.5)`, `w=snap(x+w)-snap(x)`), as do the clip boxes and the SDF radius/border (`max(1, snap(border))`); do not multiply by `scale()` anywhere else (`docs/architecture.md` → "Scale and the device-pixel grid").
4. In `OpenGLCore` a **primitive id is a fixed slot in one persistent VBO**: vertices at `id*4` (`source/platforms/renderers/OpenGLCore/openglCore.cpp`). Every slot is a quad drawn through one static 16-bit index buffer of `OpenGLCore::kSlotsPerChunk` (16383) quads, so there is no index mirror; the glyph slots likewise, through a second static buffer in freetype-gl's quad order (`v, v+1, v+2, v, v+2, v+3`, so each path keeps the diagonal its quads are split along). The slots are drawn in chunks of at most that many, one `glDrawElements` each with its own vertex array pointed at its first slot (16383, not 16384: WebGL 2's fixed primitive restart at `0xFFFF`). `GWENI_INDEX_CHUNK_SLOTS=<n>` (or `setIndexChunkSlots()`) makes the chunks smaller, which must draw the same pixels (`controltest_index_chunks`, `tests/indexChunks.cpp`). `update()` rewrites only that slot in the CPU mirror; unchanged controls leave their slots intact. A `Vertex` is 16 16-bit fields, **32 bytes**: `{style,x,y,z,tx,ty}` plus SDF fields `{lx,ly,radius,border,cx,cy,bx,by,dx,dy}`. `x,y` are signed device px (`int16_t`, ±32 K, with `z` an `ivec3` in the shader), so a rect straddling the view's top/left edge draws its on-view part; a quad with a corner outside `[-32768, 32767]` is culled by `cullOutOfRangeQuad` (all four corners at 0,0, its `style` kept), never clamped (a moved corner breaks the UV/colour/SDF interpolation and the flat half-size). Four packed RGBA pairs: `tx/ty` color0 (smooth), `cx/cy` color1 (flat), `bx/by` border (flat), `dx/dy` color3 (smooth). `style` selects the shader path (0 hidden / 1 fill / 2 image: a separately loaded texture on one of 8 image units, `radius` = unit, UV 0..65535 in `tx/ty`, tint in `cx/cy` / **3 line segment**: endpoints in `cx/cy` and `dx/dy` / **4 SDF rounded-rect** / 5 icon / **6 bilinear** / **7 checker**); `show/hidePrimitive` just toggle `style`. Text uses a separate freetype-gl buffer keyed by text id, drawn by its own program (`m_textProgram`) from a one-channel `GL_R8` coverage atlas per font (depth 1, light vertical-only autohinting, whole-pixel advances, pens and kerning, coverage applied once by the blend; see `docs/architecture.md` → "Grayscale text on the pixel grid"). **LCD subpixel text is opt-in**: `OpenGLCore::setTextAA(TextAA::LcdRGB/LcdBGR)` or `GWENI_TEXT_AA=gray|rgb|bgr` (read at construction; Grayscale by default, byte-identical to the grayscale path) loads coverage-range fonts into a depth-3 `GL_RGB8` atlas (the mode is in the `GLFontKey`) drawn with dual-source blending (`GL_SRC1_COLOR`). Its glyphs are light-hinted with unhinted fractional advances and kerning, and each pen is rounded to 1/3 device px: the quad on the whole pixel below, the image rasterised at that phase (freetype-gl's `texture_font_t::subpixel_positions` and `texture_font_get_glyph_phase`, a gweni patch; the vertex's `shift` is `phase/3`). The LCD shader branch raises light text's subpixel coverage by `c*(k+1)/(c*k+1)`, `k = setTextContrast()` (or `GWENI_TEXT_CONTRAST=<f>`, default 1) times the text colour's luminance; grayscale and SDF ignore it. A runtime switch replaces those fonts and raises `textLayoutSerial()`, which makes `Canvas::updateCanvas` re-lay the whole tree as a scale change does (`docs/architecture.md` → "LCD subpixel text"). `tools/capture_samples.sh` forces `gray`.

### Hybrid text: coverage below the threshold, SDF at or above it
`OpenGLCore::resolveFont` picks each font's atlas from its effective size `px = textPx(font) = font.size*scale()`: below `m_sdfTextMin` (default 18, env `GWENI_SDF_TEXT_MIN=<px>` read once at construction; `0` = SDF everywhere, a large value = coverage everywhere) it is a hinted grayscale coverage atlas keyed `(face, px, bold)`, laid out by freetype-gl's `text_buffer_add_text`, exactly as before; at or above it, one **R8 signed-distance-field atlas per `(face, bold)`** (key size 0), shared by every size. The SDF glyphs come from FreeType's own `FT_RENDER_MODE_SDF` (vcpkg FreeType 2.15 has the `sdf` module), through a gweni patch in `deps/freetype-gl/texture-font.c` (`texture_font_t::sdf_spread`): unhinted at 48 px, spread 6 px, unhinted `linearHoriAdvance`. `OpenGLCore::layoutSdfText` lays an SDF run out for both `measureText` and `renderText` (so `sizeToContents` fits what is drawn): metrics scaled by `px/48`, the baseline on a whole pixel. The text shader's `textMode` 1 is `smoothstep(0.5-w, 0.5+w, d)` with `w` from the field's screen-space gradient, straight alpha, and a `discard` where it draws nothing (an SDF quad reaches the spread past its ink, and must not write depth over its neighbours). A size change inside the SDF range rewrites only that run's vertex slots, with no atlas upload. `freeFont` of an SDF size frees the face's shared atlas only if no run is laid out in it; otherwise it is marked `GLFontData::freed` and deleted when its last run leaves it (`setTextRunFont`), or kept if it is used again first, so one Label changing size or being deleted leaves the face's other sizes drawing. **At a canvas scale** `renderText` draws at `px = font.size*scale()` from its snapped device-pixel origin (`TextRun::px` is in the run cache key, so a scale change re-lays a run even inside the shared SDF atlas), while `measureText` measures at `font.size` and returns **canvas units**, identical at every scale (unlike the legacy OpenGL/Software renderers, which return scaled pixels). Where `font.size` is a coverage size, `measuredPenShifts` puts each drawn glyph at its measured pen position times the scale, so the run ends where the layout sized it; `freeFont` also frees the measure-only font when no run uses it (`docs/architecture.md` → "Text at a canvas scale").

### SDF rounded-rect path (the active visual style)
Style 4 is an analytic **signed-distance-field** rounded rectangle drawn in the fragment shader (`drawRoundedRect` on `renderer::Base`): vertical gradient fill + optional border, anti-aliased with a 1 px box filter (`clamp(0.5 - d/aa, 0, 1)`, the border likewise), so a pixel-aligned straight edge covers its outermost pixel fully and nothing outside, rects that abut leave no seam and an N px border is N whole rows; only a corner arc is partly covered. The quad is exactly the rect: `lx/ly` are in half-pixel units (`±w`/`±h`, halved in the vertex shader), so odd sizes are exact. Style 5 is an **icon glyph** (`drawIcon`, `radius` = kind): a stroked SDF checkmark (0) or directional chevron (1) (checkbox ticks, combo/scrollbar arrows), and the window buttons' cross (2), dash (3), square (4) and restore (5), and a separator's rule (6). Kinds 2-6 are computed in device px over the square centred in the quad (the rule: the quad's whole length, horizontal for direction 0 and vertical for 1, through the floor of its middle), stroked `max(1, snap(1))` px (in `bx`'s high byte) with style 4's box filter, so the dash, squares and rule are whole fully covered rows and columns, and a rule is that thick wherever it lands on the pixel grid (a 1-unit rect snapped by `translate()` alone is 1 or 2 px depending on its position at 1.25 and 1.5). A style 5 pixel with less than half an 8-bit step of coverage is discarded, so it writes no depth (the textured `Separator` draws its rule one unit past it on both sides, over its neighbours). Style 3 is a **line segment** (`drawLine(id, p0, p1, thickness, z)`, `PointF` endpoints in canvas units): a capsule (round caps) `max(1, snap(thickness))` whole device px thick, each endpoint coordinate placed so the stroke across it starts on a whole px, so a horizontal or vertical segment is whole fully covered rows (columns); a pixel is covered by the exact area of it between the stroke's two edges (`pixelArea()`, a straight edge across the pixel normal to the direction from the segment's nearest point), so a thin slanted line is as bright on every row. A partly covered line pixel writes its depth up to half a layer behind its z (`mix(depth(z-0.5), depth(z), coverage)`, through `gl_FragDepth`, which every other style writes as `gl_FragCoord.z`), so the next segment of a polyline at the same z still draws over an earlier one's anti-aliased cap rim, while a fully covered pixel is blended once; one with less than half an 8-bit step of coverage is discarded, as for style 5. `renderer::Base`'s default is a filled rect along the longer axis (`docs/architecture.md` → "Line segments (style 3)"). Style 6 is a **four-corner bilinear fill** (`drawBilinearRect`, for a colour picker's saturation/value box): each vertex carries its own top-edge colour in color0 and bottom-edge colour in color3, both linear in x, so the shader's `mix` along y is exact with no diagonal crease. Style 7 is a **checker composite** (`drawCheckerRect`, for alpha previews): color0 with its alpha over 4 px cells of color1 (light) and color3 (dark), output opaque so the result does not depend on slot/draw order. Styles 4, 6 and 7 share one rounded mask, AA and border (`roundedRect()` in the fragment shader, `writeRoundedQuad()` on the CPU side); `renderer::Base`'s defaults for 6 and 7 approximate them with `drawRoundedRect`. The SDF fields are zero for all other styles, so the fill/texture/text paths are unchanged. Overlay primitives (checkmark, radio dot, arrows) must be drawn at `getZIndex()+1` so the `GL_LESS` depth test doesn't reject them behind their own background. A skin Control that draws at `+1` (or higher) must report it through `skin::Control::depthLayers()` (the z values it uses from `getZIndex()` on; `Base::renumberZRecursive` advances by it, and reads it only when the canvas renumbers, so a Control's count is fixed for its life unless it calls `Canvas::invalidateZOrder()`), otherwise its first child shares that depth; the textured `ProgressBar` reports 2 for its fill. What a Control draws in front of its own children goes at `getOverlayZIndex()`, the z after its subtree, which it reserves with `skin::Control::overlayLayers()` (read like `depthLayers()`); the textured `TextBox` draws its caret there, its selection at the text's z (`TextBox::getTextZIndex()`), and a text run's glyph i sits at `z+(i+1)/(glyphs+1)`, so a rect at the Text's z is behind every glyph (`docs/architecture.md` → "The TextBox caret and selection"). The textured skin drives it through `tokyonight::Surface` + `paintSurface()` (`include/gweni/skins/textured/tokyoNight.h`) and the `RoundedPrimitive` helper (`texturedPrimitives.h`); each control renderer's `update()` just picks a `Surface` for its state. The default theme is **Tokyo Night** (dark, blue-toned): surface fills are mutable globals in `tokyoNight.h`, text/line colors are set in code by `TexturedSkin::setThemeColors()`, and `renderText` bakes the control's draw color into the glyphs so per-control text colors apply. **The theme is swappable without recompiling**: an optional `"theme"` object in `resources/DefaultSkin.json` (`surfaces` + `textColors`) is loaded by `TexturedSkin::loadTheme()` and overrides any surface (by name, via `tokyonight::surfaceRegistry()`) or text color; omitted entries keep the compiled defaults. A skin config that cannot be used (missing, a directory, unreadable, not parsing, or not a JSON object) makes `TexturedSkin::init` print one stderr line naming it and return `false` with the skin still usable: every registered surface in `colors::Missing` (magenta, `colors::MissingDark` borders, through `tokyonight::setAllSurfacesMissing()`) and the text colours at their compiled defaults. An atlas texture (`textureFileName`) that does not load is reported and fails `init` too, but the rest of the config, the theme included, still applies. A missing image (`drawMissingImage`) is the same magenta. The legacy 9-slice atlas path (`BorderedPrimitive`) still exists but is no longer used by the converted controls.

When adding or modifying a control, the rule is: mutating anything visual must call the appropriate `addStateChange(...)` (or `addStateChangeRecursive`) so the primitive gets regenerated — otherwise the change won't appear. `redraw()` does this for interaction state (hover, press, focus, disabled): it re-runs `updateColors()` and marks `StateChange_Background` on that control only, then sets the canvas's `needsRedraw()` flag; it no longer walks the ancestors. Issue it from the update phase, since `doRender` clears the state change after rendering. Conversely, don't redraw unconditionally; that defeats the whole design.

Every control type needs a skin renderer of its own or an intermediate ancestor's (`TextBoxNumeric` draws as a `TextBox`). `Base::setSkin` looks one up by type name, walking up the parent types; if the walk ends at the skin's `Base` entry, it prints `gweni: no skin renderer for <TypeName>` on stderr, once per type and in every build, and records the type in `gweni::controls::typesWithoutSkinRenderer()`. ControlTest exits non-zero if that set is not empty, so `controltest_teardown` (which builds every demo) fails. A type that draws nothing by design (a layout or pure container, a part its parent's renderer paints, a control drawing itself in `render()`) opts out with `GWENI_DRAWS_NOTHING` in its class body, an override of `drawsNothing()` that holds for that type only, so a subclass with no renderer is still reported (`SliderBar` derives from `Dragger`, which opts out). A visual control still waiting for its renderer gets an empty one registered with `GWENI_PENDING_RENDERER` in `texturedControls.h`, citing the issue that tracks the real one, not a `drawsNothing()` override. Renderer names are bare type names, so the `property::` controls `Text`, `CheckBox` and `ComboBox` get the real controls' renderers: those `dynamic_cast` and draw nothing for anything else.

**Current state vs goal:** incremental upload is in place — `OpenGLCore::flush()` records which primitive slots were written, uploads only those as coalesced `glBufferSubData` ranges, and skips the transfer entirely when nothing changed (the draw still happens every frame). A slot counts as changed only if its bytes differ, because the skin re-emits unchanged controls every frame. Buffers are sized by a grow-only `glBufferData`, which re-sends everything for that frame. Glyphs outside the ASCII cache are rasterised lazily into the CPU font atlas, and `flush()` uploads the rows they touched (a dirty row band added to the vendored freetype-gl's `texture_atlas_t`) before drawing. `GWENI_UPLOAD_STATS=1` prints per-frame upload calls/bytes (atlas uploads separately, the clip-box buffers included); `GWENI_TEXT_DEBUG=<substring>` dumps `measureText`'s glyph metrics and the text mirror slots for matching strings; `GWENI_CLIP_DEBUG=<inset px>` shrinks every clip box by the inset on each side, so the shader clipping shows on screen. Clipping is done in the fragment shaders: every primitive and glyph slot carries the `clipRegion()` it was drawn in (a `Box`, scaled and clamped), read from a `GL_RGBA16UI` buffer texture. The primitive shader reads it at `slotBase + (gl_PrimitiveID >> 1)`: each chunk is drawn from index 0 of its own slots with 2 triangles per slot, and the `slotBase` uniform is the chunk's first slot. Text is drawn as one `glMultiDrawElements` per font atlas and index chunk its runs reach (one per atlas until the glyph slots outgrow a chunk), over the glyphs in use of the runs laid out in that font that are not hidden (each `TextRun` records its `GLFontData`, which lists its runs; `buildTextDrawList` splits them at the chunks' edges), so the text shader takes the slot from `slotBase + (gl_VertexID >> 2)` instead. That draw list is what keeps a hidden or freed run and a shrunk run's tail off the screen; no index is written for them, so hiding, showing or shrinking a run uploads nothing but its changed vertexes. A Vulkan backend would do the same with device-local buffers + a staging upload. Each control with `shouldClip()` (all but `TabStrip`, `TabButton` and `Text`) narrows the region for its children in `Base::renderRecursive` (`addClipRegion`: its bounds at its absolute origin, intersected with the parent's region; no overlap gives an empty rect), while its own `render()` stays clipped by its parent's. A region changes only with an ancestor's bounds, and `onBoundsChanged` marks that subtree, so the new boxes reach exactly the controls under it. Clean, fully clipped subtrees are still walked like any other: only dirty ones are re-stamped (with the empty box), nothing is culled on the CPU. Still open: cache-to-texture and free-slot compaction — see `docs/architecture.md` → "Current state vs. goals".

### Controls
- Construct via the canvas: `canvas->newChild<SomeControl>()` or the `newControl<T>(name)` / `T::newInstance(name)` factory pattern. Controls form a parent/child tree (`Base::List`), set up by `setParent`.
- `Separator` (`controls/separator.h`) is a 1-unit rule, horizontal or vertical (`setVertical()`, which also makes it grow along the rule only), as long as its dock or layout makes it, with an optional caption (`setText`, imgui's SeparatorText) `captionInset()` in from the left that the rule runs around; `MenuDivider` derives from it, so menu dividers draw with the same renderer. `Bullet` (`controls/bullet.h`) is a Label with a circle in its text colour in a left column of its font's size plus a gap (imgui's Bullet/BulletText). SeparatorDemo shows both.
- `TextBox::setPlaceholder` shows a hint in the skin's `PlaceholderText` colour while the box is empty and unfocused: a second Text child that is not content (not `getText()`, not in the box's size) and is only ever shown or hidden (`docs/architecture.md` → "The TextBox placeholder").
- `Selectable` (`controls/selectable.h`) is a row that highlights while hovered and stays highlighted while selected (imgui's Selectable): a click toggles it (`setToggleable(false)`: only selects), Space and Return press it, `onSelect`/`onDeselect` fire on a real change. `SelectableGroup` is a plain object holding at most one selected row (`getSelected()`, `onSelectionChange`). An idle row's slot is hidden, not drawn transparent (`docs/architecture.md` → "Selectable rows"). SelectableDemo shows both.
- `ProgressBar::setIndeterminate(true)` draws a segment moving along the track in the fill's slot instead of the fill (`indeterminateSegment`, whole units cut to the track), marking `StateChange_Background` only on a frame that rect changes, with the auto label empty; `setIndeterminate(false)` gives back the stored progress and its label (`docs/architecture.md` → "The indeterminate ProgressBar"). ProgressBarDemo has one of each orientation and a button that stops and starts them.
- `Base::setContextMenu(menu)` / `createContextMenu()` give a control a right-click menu: a right press on it (or on a descendant with none) opens it at the cursor, flipped and kept inside the canvas by `Menu::placement` once it is laid out, after the press has closed the open menus; Escape, a click outside, a chosen item, and the control hidden or deleted close it. One is open per canvas (`Canvas::shownContextMenu()`). A created menu is the control's, one set from outside stays its creator's (`docs/architecture.md` → "The context menu"). ContextMenuDemo shows two.
- Tooltips (`setToolTipText`, `setToolTip(control)`) are shown by the canvas in its one `ToolTip` box (`controls/toolTip.h`), decided in the update phase after a hover delay and placed below the control, never drawn after the walk; the box is kept as the canvas's last child so it is numbered above everything (`docs/architecture.md` → "The tooltip: a canvas-level overlay").
- Each control type exposes static/virtual `getTypeName()` and `getControlName()` for runtime identification and the reflection-ish `getControlType(name)` lookup.
- Layout helpers (`align.h`, `controls/layout/`) and docking (`DockPosition` in `uiTypes.h`) handle positioning.

### Skins
A skin is constructed around a renderer and `init()`'d from a resource: the textured skin loads `DefaultSkin.json` (atlas description) + a TTF font. `texturedControls.cpp` / `texturedPrimitives.cpp` map each control type to its primitive layout in the atlas.

### Events
`event::Handler` is a base of `controls::Base`. Hooks carry an optional `event::Packet` (a `std::variant<Base*, String, int, float, size_t>`) delivered via `event::Info`. Use `Packet::isControl()/isString()/...` + `get<T>()` to unpack.

## Conventions
- C++17, `lowerCamelCase` for methods/functions, `PascalCase` for types, member fields prefixed `m_`.
- Public symbols crossing the library boundary are tagged `GWENI_EXPORT` (`export.h`).
- `gweni::String` / `gweni::Point` / `gweni::Rect` / `gweni::Color` / `BoundingBox` (aliased to `Margin`/`Padding`) come from `platforms/platformTypes.h` and `uiTypes.h` — use these rather than raw types.
- Filesystem backend is selected at configure time via `GWENI_USE_FILESYSTEM` (std / experimental / boost) based on compiler; code must go through that macro, not include `<filesystem>` directly.
- Verbose per-control debug output (`logUpdates` → `printf`, plus `DEBUG_ID` and `DEBUG_LAYOUT` in `base.h`) is off by default and enabled by configuring with `-DGWENI_DEBUG_LOGGING=ON`; expect verbose stdout when running such a build. `DEBUG_ID` also appends each control's id to label text, so that build looks different too.
